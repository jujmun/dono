## Detail on the money-critical items (independently re-verified)

### Item 2 — Fee calculator
`convex/lib/platformFee.ts` implements a **flat 5% + 20p combined envelope**, split by subtracting a **flat-rate estimate** of Stripe's cost (1.5% + 20p — not a real, per-transaction Stripe cost lookup):

```ts
export const PLATFORM_FEE_RATE = 0.05;
export const PLATFORM_FEE_FIXED_MINOR = 20;
export const ESTIMATED_STRIPE_PERCENT = 0.015;
export const ESTIMATED_STRIPE_FIXED_MINOR = 20;
```

Dono's take is whatever's left of the envelope after the Stripe estimate — not a fixed 3.5 percentage points. On a £100 donation this happens to land near 3.5%, but the formula isn't "Stripe's actual cost + 3.5pp" and doesn't hold that shape at other amounts (e.g. a £1 donation nets Dono £0). There is **no FX/currency-conversion surcharge logic anywhere** — every PaymentIntent is hardcoded to `currency: "gbp"` (`convex/stripe.ts:255,362,702`), so there's no code path that could even detect a non-GBP card. This is a genuine absence, not a wrongly-unconditional 2% charge — but the requirement itself doesn't exist yet.

### Item 3 — Fee-cover toggle default
```ts
// app/campaigns/[id].tsx:86
const [coverFees, setCoverFees] = useState(true);
```
This is backwards from spec and from Donor Terms §6.2(b): the donor currently defaults into covering fees, rather than the campaign absorbing them unless the donor opts in. This is the single most concrete, most easily-fixed compliance bug found in the whole audit. The checkout UI also only ever surfaces "total charged" and (buried in a checkbox label) "amount to campaign" — never the Dono fee and Stripe fee as their own line items, so the "5 distinct figures" requirement in Donor Terms §6.3 isn't met even before the default-state issue.

### Item 5 — Refund execution model
The code and the *finalized* legal policy have diverged, and the legal doc already knows it:

- **Code** (`convex/refunds.ts` `adminDecide` → `convex/stripe.ts:938-950` `processApprovedRefund`): Dono's backend calls `stripe.refunds.create(..., { stripeAccount: connectedAccountId })` directly against the connected account, after admin approval. It never passes an `amount`, so **every refund executed this way is a full refund — there is no partial-refund capability in this path.**
- **Refund and Dispute Policy §6.1** (`dono-brain/terms/07_dono_refund_and_dispute_policy.md`): *"The Campaign Owner executes the refund from their own Stripe dashboard. Dono does not process the refund and does not initiate it through Stripe's API."*

These are mutually exclusive models. The code implements the older §21.5 model from the legal-terms-context-handoff draft (Dono API-initiates, gated by owner+admin approval); the finalized policy has since reversed that. This needs a product/legal decision before either side is "fixed" — see Cross-cutting blockers.

Separately: `convex/stripe.ts:831-912` (`refundAndCancelSocietySubscriptionForNoCampaigns`) is a genuinely automatic, no-approval refund path — but it's scoped to society subscription billing (refunding a charge when a society has zero active campaigns), not campaign donations, so it doesn't violate the "no platform-initiated donation refund" requirement, but it's worth having on your radar as the one unilateral refund trigger in the codebase.

### Item 23 — Age gate
```ts
// components/donate-sheet.web.tsx:260 and donate-sheet.native.tsx:230
ageAttested: true,
```
Both donation UIs hardcode this to `true` on every submission — there is no actual checkbox distinct from the combined legal-acceptance checkbox (`components/legal-acceptance-checkbox.tsx:42`, *"I am at least 18 and I agree to the [Terms]..."*). Server-side, `convex/stripe.ts:203-208` and `convex/legalInternal.ts:14` just check that this boolean is `true` — which it always is by construction. Stripe Identity's `verifiedDob` exists in the codebase but is scoped to campaign/society creators only, disabled by default (`STRIPE_IDENTITY_ENABLED` env flag), and never referenced by any age-gating logic anywhere. **Donor age verification is currently self-declaration in name only** — there's no meaningful way for a donor to *not* attest, since the client never sends anything else.
